Go GC解析：从标记-清除到三色并发与混合写屏障

Go 垃圾回收（Garbage Collection）的演进核心，是一部不断压缩 STW（Stop The World） 暂停时间的优化史。下面通过手绘笔记式的 10 个独立分步交互动图，系统拆解 Go ≤ V1.3 标记-清除与 STW 提前优化、Go V1.5 三色并发标记与无 STW 漏标危机、强/弱三色不变式、插入写屏障（栈堆差异与 STW 重扫栈）、删除写屏障（起始快照与浮动垃圾），以及 Go V1.8 混合写屏障的初始化机制与堆→栈、栈→栈、堆→堆、栈→堆四大核心迁移场景。

Version Evolution · Summary
Go 版本 核心算法 / 机制 栈空间策略 堆空间策略 STW 与核心特点
Go < V1.3 普通标记-清除
Mark & Sweep		 全程暂停扫描 全程暂停标记与清除 STW 包裹整个 Mark + Sweep；停顿极长，易产生堆内存碎片。
Go V1.3 标记-清除（STW 提前释放） Mark 期间 STW Mark 后解除 STW，Sweep 并发 减少 Sweep 阶段的停顿，但 Mark 全程仍需 STW，大堆延迟依旧很高。
Go V1.5 三色并发标记 + 插入写屏障（强三色不变式） 不开启屏障；标记结束后 STW 重扫栈 开启插入写屏障（新增引用时新下游染灰） 大幅压缩 STW；但结束时仍需 10~100ms STW 重扫栈区，防止栈上漏标。
对比方案 三色并发标记 + 删除写屏障（弱三色不变式） GC 开始时 STW 扫描栈记录起始快照 开启删除写屏障（断开旧引用前旧下游染灰） 结束无需重扫栈；但回收精度低，断链对象会作为浮动垃圾活过本轮 GC。
Go V1.8+ 三色并发标记 + 混合写屏障（变形弱三色不变式） 不开启屏障；初始并发扫栈全黑，GC 期间栈上新建对象直接为黑 开启混合写屏障（删旧下游染灰 + 添新下游染灰） 彻底消除结束时的栈 re-scan，几乎无需长时间 STW（亚毫秒级），兼顾效率与安全。
